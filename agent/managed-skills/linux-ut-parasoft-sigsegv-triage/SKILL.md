# Parasoft ExecViol Triage (linux-ut split-exec, 10028)

## Crash mapping authority
Map crashes from `reports.N/report.xml` ExecViol traces (testName + fileName/ln). NEVER binary-grep logs/violations dirs — overcounts and mislabels projects.

## ExecViol cat classification (report.xml)
- `cat=1`: Assertion failure — real test logic failure.
- `cat=15`: Stub callback problem — two sub-types:
  - `"fn" is never called in the current configuration` (type=auto, test path doesn't invoke fn)
  - `cannot use Stub Callbacks for "fn"` (type=orig or static-inline macro)
- Gate (`src/report.rs`): `CategoryErrors cat=0|5` → execution_problem_count (FATAL). cat=15 ExecViols are summarized under cat=0 via SubCategoryErrors subCat=15 → **counted as execution problems, blocking**.
- `single_project_metrics.json` labels cat=15 as "Test Problems" (different from gate's execution_problem_count).

## 0 executed diagnosis
Suite reports 0 executed with rc=0 and no visible error → read `report.xml` TestingProcessProblems/Error val: it carries the real cpptest_testrunner.c compile/link error (execution step silently skipped; log lacks the "Running tests with QEMU crash recovery" line). Known causes: undeclared symbols left by commented callbacks in other TUs; BUCKET_V2 comment trailing text (below).

## cat=15 removal safety check (CRITICAL)
cat=15 does NOT mean the test body passed. The stub config error can **abort the test body before assertions evaluate**.
- Before removing a `CPPTEST_REGISTER_STUB_CALLBACK` line, READ the test function body.
- If the body asserts the callback's **return value** (e.g. `0x5a5a1234 == readl result`) or **call count** (e.g. `raw_readl_calls == 1`) → removal will cause NEW cat=1 failures. Do NOT remove — convert to per-TU hook or variable-driven stub instead.
- If the body does NOT depend on the callback (e.g. `(void)v` discards result, or other callbacks drive assertions) → removal is a true no-op, safe.

## Dangling reference after BUCKET_V2 disable
When commenting `CPPTEST_TEST(registration)` but the function body still has active `CPPTEST_REGISTER_STUB_CALLBACK("fn",...)`:
- If fn is in a **different TU** (e.g. `of_clk_set_defaults` in clk-conf.c, not the INCLUDED_TO source) → macro expands → symbol undeclared → **compile failure → 0 executed**.
- Fix: also comment the REGISTER/UNREGISTER lines in the body (STUB_CB_DISABLED marker).
- If fn is in the **same TU** (e.g. `clk_find_hw` in clk.c) → symbol visible → no dangling, body compiles fine.

## BUCKET_V2_DISABLED comment format (testrunner compile failure)
Comment MUST be exactly `/* BUCKET_V2_DISABLED_EXEC_PROBLEM: CPPTEST_TEST(...); */` with NOTHING between `;` and `*/`. Parasoft's testrunner generator extracts `CPPTEST_TEST(...)` from inside comments INCLUDING trailing text; e.g. `; -- clk_find_hw type=orig real in clk.c)` emits `-- ...` as generated C code → undeclared identifiers (`of_clk_set_defaults`, `clk_find_hw`) → testrunner compile error → 0 executed. Fix: strip all text between `;` and `*/`. Sweep with `grep -rn '\-\- [a-z]' <projects>/*/tests/`.

## Fix patterns

### type=auto hw-core deref (clk_hw_get_rate/parent/flags/name/is_prepared)
- stubconfig type=orig→auto PER PROJECT + manual `CppTest_Auto_Stub_fn` in stubs/user/ (non-void: `__return` safe default + callback dispatch + return).
- NEVER type=auto the project whose own source is under test.

### static-inline MMIO macro (readl_relaxed/__raw_readl/__raw_writel)
- io.h overlay in `local_fake_headers/linux/io.h` (compile_commands -I puts local_fake_headers FIRST → global shadow).
- For `readl_relaxed`: per-TU `linux_ut_readl_relaxed_hook` (static, default NULL→0). TestSuite INCLUDED_TO source.c → same TU → hook shared.
- For `__raw_readl`/`__raw_writel` (also macro-ized): add `linux_ut___raw_readl_hook` / `linux_ut___raw_writel_hook` (same pattern, default NULL→0/no-op, backward-compatible). Convert test callbacks from StubCallInfo style to hook-style `u32 hook(addr)` / `void hook(u32,addr)`.
- For stateful PLL tests: setUp installs hook, tearDown clears (PLLFIX pattern: `linux_ut_readl_relaxed_hook = mmio_read; ... linux_ut_readl_relaxed_hook = 0;`).

### readl WEAK + wait loops (SIGALRM prevention)
- Disabling readl callback → WEAK returns `linux_ut_readl_result` (default 0) → `wait_cpu_in_reset`/`wait_for_mask` loops poll readl until bit set → infinite loop → SIGALRM.
- Fix: set `linux_ut_readl_result = 1` before the wait call, reset `= 0` after.

### NULL-arg boundary autogenerated tests
- Comment the ACTIVE `CPPTEST_TEST(...)` registration as `/* BUCKET_V2_DISABLED_EXEC_PROBLEM: CPPTEST_TEST(...); */`, keep the function body.
- Never double-comment already-disabled lines.

### clk_find_hw / of_clk_set_defaults (type=orig, real in same TU)
- Cannot stub (type=orig, dispatcher not applicable for same-TU real definitions).
- Suite-side refactor: remove callback + adjust assertions to match real function behavior (e.g. clk_find_hw with empty clk_lookups → returns NULL).
- Or disable (BUCKET_V2) if the test fundamentally needs the stubbed return value and no fixture is available.

### Variable-driven STRONG stub overrides (orig-stub assertion failures, option a)
When callbacks are unusable (type=orig cat=15) but the test asserts stub return values, add STRONG definitions reading control globals in a project-scoped stubs/user/ file (e.g. `stage6_var_drive_stubs.c` in `projects/kbuild-stage6-extra/stubs/user/`); defaults match WEAK defaults so other tests are unaffected. STRONG wins over `CPPTEST_WEAK` reduced-prototype defaults at link; adding the file does NOT modify prep WEAK anchor text.
- **Placement rule**: ONLY in the affected project's per-cache `projects/<proj>/stubs/user/`. NEVER in `ws.N/kbuild/stubs/user/` — that tree links into EVERY split project → multiple-definition link failures (e.g. STRONG `clk_set_rate`/`__clk_lookup` collides with kbuild's own). If mistakenly placed there, restore from `.bak-*`.
- Index-aware trick: `clk_hw_get_parent_by_index` returning NULL for index 0 and the variable for index!=0 makes `parent != old` in `tegra210_clk_emc_set_rate` so the `clk_prepare_enable` error path runs.
- Test side: `extern`-declare the globals in the TestSuite, set once (`linux_ut_clk_hw_get_parent_by_index_result=&parents[0]; linux_ut___clk_lookup_result=(struct clk*)1;`), sync per round (`linux_ut_clk_hw_get_rate_result=...; linux_ut_clk_set_rate_result=...; linux_ut_clk_get_rate_result=...;`), reset all at end.
- Sync per-cache copies individually (multiple caches coexist, e.g. 125807 + 141258).
