# Relocated linux-ut workspace: auto-stub path rebase

Use when `run_all.sh` fails with `STUB SYNTAX FAIL` / `fatal error: <old-root>/...: No such file or directory` after unpacking `ws.full.tar.zst` at a different root (e.g. `linux-ut-reloc-links-*`).

## Root-cause order (check in this sequence, cheapest first)

1. `ws/kbuild/stubs/autogenerated/auto_*.c` — `#include "<old-root>/..."` absolute paths baked into the validated stub source. Fix in place AND in `validated_autostubs_*/auto_*.c` (the restore copy source) or the next run regenerates the old paths.
2. `.cpptest/kbuild/file-data/*/{modification-data,ipro-data,harness_*.c}` — LSI text caches carrying the same old-root prefix; sed them or runs re-poison the stub.
3. `restore_*_validated_stubs_*.py` (workspace-private, invoked from run_ut.sh before cpptestcli) — overwrites the stub from the validated source and pins a source SHA. After rebasing the source file, recompute sha256 and update the script's `SHA = "…"`, and (best) patch the script to rebase the copied stub post-`shutil.copy2` (idempotent) so future unpacked copies self-heal.
4. `ws/.provenance.json` — any content edit triggers `PROVENANCE_MISMATCH: workspace assets stale`. Delete it to take the legacy "runs against the current ws as-is" path (WARNING, not fatal).
5. Stale binaries — delete `.cpptest/**` `*.o` / `kbuildTest.exe`; they embed old paths but are regenerated.

## Rebase recipe

- Replace `<old-root-parasoft-ws-path>/` with the current workspace-root path + `/` — e.g. old `/home/melo.sf/LFD_MX_CodeBase_QEMU/linux-ut/parasoft/kernel-block/` → `$RELOC/parasoft/kernel-block/`.
- CRITICAL gotcha: the include paths already end with `…/<ws-name>/build/…`. If you substitute with `str(root) + '/<rel-subdir>/'` instead of plain `root + '/'` you manufacture `…/<w>/<w>/build/…` double prefixes. Symptom: second run now fails on a *new* nonexistent doubled path. Fix: collapse the duplicate segment (`'/k/k/k/' → '/k/k/'`) then rebase with the plain-root + '/' form.
- After patching, verify `sed -n '18p'` (or grep the failing include line) shows the single, existing path before rerunning.

## Verification chain

`LANG=C.UTF-8 LC_ALL=C.UTF-8 ./run_all.sh` → require: `ALL CHECKS PASSED (stage N)`, `0 failed / 0 execution problems / 0 assertion failures`, `reports.full/validation.json` status=PASS/acceptance=true/scope=full, and `ws/.stage-gate-pass` `report_sha256` == `sha256sum reports.full/report.xml`. A `static coverage conflict` WARNING (e.g. bio/crypto inline conflicts) is informational, not blocking. `ZERO_TESTS_EXECUTED` + `error preparing instrumentation / symbols data` on an auto stub = path still stale somewhere — re-audit, don't rerun blindly.

## Boundaries

Edit only workspace-private files (`run_ut.sh`, `restore_*_*.py`, `validated_autostubs_*/`, `ws/**`). NEVER touch shared tools (scripts/, src/, run_all.sh), never the kernel source. Keep `.bak-*` backups of every patched script/source; normalized `.cpptest` caches are regenerable and need no backup.
